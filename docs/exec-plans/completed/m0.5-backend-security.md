## Scope

- Adopt the owner reference into bounded first-party packages for authorization, publishing, security, catalog, credentials and xAPI ingestion.
- Add forward-only PostgreSQL migrations with RLS, immutable published records, append-only audit events, credential controls, an empty versioned learning-objective registry and empty region-configuration schema.
- Add the provider-neutral `IdentityProvider` contract and a test-only fixture provider. Auth0, Clerk and WorkOS adapters remain deferred to M0.6.
- Add a framework-neutral API boundary with health, public credential verification and authenticated xAPI ingest handlers.
- Preserve the reference package's 31 unit and 14 database tests, then add monorepo integration tests around identity and API boundaries.
- Record reference provenance, architecture decisions, dependency metadata and the M0.5 threat model.

## Out of scope

- `apps/learning`, `apps/admin` and all learner/admin UI.
- Auth0, Clerk or WorkOS SDKs and production identity-provider configuration.
- Production Redis, KMS/HSM, object storage, email, commerce or deployment configuration.
- Course objectives or other curriculum text; the registry remains empty for curriculum staff.
- Real accreditation, credential, learner, partner, property or regional records.
- M1 simulation content and final 3D art.

## Acceptance criteria

1. All 45 owner-reference tests pass after monorepo adoption.
2. Learner data is denied by default, separated from housing/property roles and protected by RLS.
3. Publication requires the exact content hash, every required human approval, a non-3D path, a passed claims check and at least two distinct approvers.
4. xAPI ingest rejects spoofing, unknown keys, stale/future/oversized payloads and duplicates.
5. Credentials are eligibility-gated, signed, verifiable, expirable and revocable without mutable payloads.
6. Only a dedicated credential issuer role can insert issued credentials; only a dedicated commerce role can write enrollments.
7. Fixture identity cannot be enabled in production.
8. Health and verification responses disclose no secrets or learner PII.
9. Full format, lint, typecheck, test, governance, license, audit and build checks pass.

## Allowed dependency change

- Add `@electric-sql/pglite` as a development-only database-test dependency. Select the newest stable release at least 14 days old under Simulation Lab §7.6. No other third-party dependency is added.

## Security and privacy notes

- Production keys remain in KMS/HSM; generated Ed25519 keys are test-only.
- The in-memory audit log and token bucket remain test or single-process reference implementations; production persistence is PostgreSQL and the future distributed limiter is Redis.
- No sensitive learner free text enters xAPI, audit metadata, logs or analytics.
- Retention values remain owner/counsel decisions and are not silently enforced as final policy.
- No network endpoint, identity SDK, external database or cloud service is configured in this milestone.

## Three largest risks

| Risk | Mitigation |
|---|---|
| Authorization drift between TypeScript and PostgreSQL | Mirror denial cases in the 45 reference tests and keep both policy surfaces owner-protected. |
| Fixture or in-memory components reaching production | Production-environment guards, explicit names and documentation; no production adapter is supplied. |
| Credential or claims language exceeding verified authority | Draft-only seeded definitions, accreditation checks, deterministic claims lint and no issuance endpoint without an injected issuer. |
